# PuriCat — feature status

What is built, and how each part is known to work. The overview, downloads and screenshots are in [README.en.md](README.en.md) (Thai: [README.md](README.md)); how things were tested is in [TESTING.md](TESTING.md).

> **Status: early development.** Phase 1 (runnable foundation) is complete; Phase 2 (database connectivity), Phase 3 (editing), Phase 4 (SQL and schema) and Phase 5 (AI) are partially complete. This build can connect to MySQL and PostgreSQL servers and **open a SQLite database file**, browse tables and **filter their rows**, **edit data in tables that have a primary key** (spreadsheet-style, staged until Save), load a block copied from a spreadsheet, or a **CSV or Excel file**, with the **Smart Paste wizard** (INSERT / UPDATE / UPSERT matched on a unique key, previewed before anything runs), **run SQL in query tabs** (each tab on its own connection, with a row-impact guard, a row cap, Stop, history, and export to CSV / JSON / XLSX), and **chat with an AI** through a Claude Code or Codex CLI you have installed and signed in to. By default the AI is given the schema (names and types, never rows) and **no tools**: it only writes text, and SQL it suggests runs only when you open it in a query tab and run it yourself. You can turn on **database tools** for it: it can then look up the structure of the database in front and — only if you allow rows — run read-only queries; a change is a proposal that PuriCat runs only after you have read and approved it. The tools are verified with Claude Code; **no Codex turn with tools has been observed**. It can **create, edit and drop a database** on a MySQL or PostgreSQL server from forms that show the exact statement before it runs (edit: the default character set and collation on MySQL, the name and the owner on PostgreSQL; a drop asks for the database's name to be typed). From the menu of a table or a view it can **show the definition, rename, empty and drop** — on MySQL, PostgreSQL and SQLite, again with the exact statement shown first; emptying and dropping ask for the name to be typed, and on PostgreSQL the definition of a table is text PuriCat puts together from the catalogue, labelled as such. It can **create a view and change a view's query** from a form that holds the query alone, on the same three engines: the rows of the query can be previewed first, read-only, and the statement PuriCat writes around the query is shown before it runs. Those are the only schema changes it makes through a form: it cannot create a table, or change a table's columns, keys or indexes, except as SQL typed in a query tab. On a MySQL or PostgreSQL server it shows **the accounts and what each may do**, and can **create a user from a template** — an application user or a read-only user for one database, or an account with no privileges yet — **change a password** and **drop an account**, each with the statements shown before they run and the password masked unless asked for; privileges are not granted one by one. It makes **backups** of a MySQL or PostgreSQL database, by hand and on a schedule, and can **restore one of them into a new database** on the same connection. This build cannot import more than 10,000 rows at once, tunnel over SSH, connect to SQL Server, restore over an existing database, or encrypt a backup. **Not ready for production data.** The macOS download is signed with a Developer ID and notarized.
